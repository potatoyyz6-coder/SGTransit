# 自选站点与附近候选

实施日期：2026-10-24；收尾复核：2026-10-25（SGT）。本地研究功能，非实时导航服务；本轮无 API 请求、无新增采集计划。
与 OpenAI Codex 协作实现。未自动提交或推送本轮改动。

## 使用

从仓库根目录运行 `python -m experiments.local_app`，打开终端显示的本机地址。
端口被占用时使用 `--port 8766`。勾选“自选站点与附近候选”：

1. 选择覆盖网络，按站名或 ID 选择起终点中心站。
2. 指定新加坡时间的参考日期与时刻，设置 0–2000 米发现半径（默认 400 米）。
3. 点击“查找附近站”，确认每端 1–3 个站，然后“计算参考”。
4. 点击方案，查看实际端点、服务方向、换乘站变体和时间分项；可推演途中继续坐/换车。

当前覆盖网络是两个原案例子网，以及完整导入的 97 路两个历史方向。
这不是给全岛任意站点换一个输入框：全量目录 5,205 站与路由覆盖是两回事。
目录能搜到而路网不能规划的站会显式标记，不能静默替换。

## 时间含义

- 接驳留空：在所选上车站于参考时刻就绪的条件下比较公交段；接驳和全程均未知。
- 手填起端接驳：先推迟上车站就绪时刻，再估计等待、上车和历史运营窗口。
- 两端均手填：另显示公交段加接驳的参考总时间。手填时间不是验证过的步行可达性。
- 直线距离仅用于发现候选。不同上车站不共享“先到先坐”；途中没有新增跨站步行边。
- 模型仍为 20 km/h、每原始路段至少 0.5 分钟、headway 15 分钟、每次上车平均延误
  1.5 分钟，换乘缓冲可选 1–5 分钟。不是某个未来日期的实时班次或赶车概率。
  日期仅区分工作日、星期六和星期日的历史窗口，不含公共假日或临时改道核验。
- 未知历史运营窗口的拓扑候选保留并标记未知；已知窗口外/限时服务不进入默认参考。
  此行为只属于新离线参考路径，没有放宽历史 ETA 回放的证据门槛。

## 搜索与状态

小于等于 30 站的声明路网使用现有有向枚举；较大路网使用现有目的地有界走廊搜索。
不启用碎片实验算法。单对至多 10,000 候选和 100,000 次扩展；最多九对共享 20,000
候选及 200,000 次扩展预算。失败分支的已消耗工作也计入总预算。
枚举内部会在第一个超限事件抛出异常，因此统计计数可能比阈值多 1；没有把超限候选当作完整结果。

| 状态 | 含义 |
| --- | --- |
| `unknown_stop` | 站号不在冻结目录内 |
| `outside_network` | 目录有该站，所选路网尚未覆盖 |
| `unreachable_within_bounds` | 声明路网与约束内无解，不代表现实无公交 |
| `budget_exceeded` / `budget_not_searched` | 单对超限或总预算用完，不能断言无路 |
| `bounded_candidates` / `bounded_no_candidate` | 有界候选搜索，仍可能遗漏路线 |
| `operating_status: unknown` | 站序可行，但历史运营窗口缺失 |

候选缓存键包含网络哈希、实际端点、路由参数和搜索方法。估时每次按日期与接驳重新计算。
整个查询另有包含出发时刻和接驳参数的哈希；途中状态绑定该查询，并只比较相同实际端点、
相同已行驶前缀的后续走法。状态仅驻内存，最多三个查询、三小时有效期。
缓存最多 24 组、累计 20,000 条拓扑候选，不保存地址或乘客身份。

摘要最多 16 个“端点 + 有向服务序列”组；保留每个有模型可用路线的端点对至少一组，
再补充预计较快、少换乘、少等待的组。组内换乘站变体不被丢弃；所有搜索返回的候选参与途中比较。
更改输入不会改变已经生成的旧查询状态，必须重新计算才得到新查询。

## 有向导入与扩区

`src/sg_transit/directed_import.py` 保存服务、方向、原始站序、站号、访问次数、累计距离和窗口。
不会去重重复站点，也不会拆开同车身份来绕过求解器限制。缺段、重复停站及缺失模式分别报告覆盖缺口。
重复停站模式尚不能进入当前求解器，这是明确的剩余能力限制，不是“已支持全岛”。

`experiments/station_networks.py` 选择 97 的两个完整方向，导入 102 个不同站点、103 个停站事件。
它复用原仓库的历史 BusStops/BusRoutes 文件，核对原始数据哈希并记录事件库存哈希；没有下载新数据。
每个方向的中间站都与原始 CSV 比较。后续新增区域应先在这里声明方向模式，再验证覆盖缺口及预算。

| 需求 | 可重复验证的依据 |

| 未写死的端点、原快捷案例不回归 | `tests/test_station_planner.py`；`tests/test_local_app.py` |

| 最多 3 × 3 组合、端点不被服务序列去重 | `test_nine_pairs_include_unreachable_and_nearby_can_have_no_benefit` 及多端点重复性测试 |
| 有收益/无收益都允许、未知接驳不当作零 | 合成端点测试及 `test_access_changes_readiness_before_windows_egress_unknown_separate` |
| 接驳先移动就绪时刻再检查窗口 | 同上，构造末班窗口边界，接驳 1 分钟即可改变适用状态 |
| 继续坐不再等待、历史与端点隔离、禁止实时调用 | `test_custom_onward_uses_projected_departure_and_keeps_endpoints` |
| 重复事件保留但不虚构换乘、缺段与错误源数据 | `tests/test_directed_import.py` |
| 扩区多个新端点、连通性、耗时和内存 | `python -m experiments.station_planning_check`；`results/station_planning/workload.md` |
| 桌面/手机、手填接驳、扩区、显示未知 | `tests/station_ui_browser.js`，通过 Playwright CLI 执行 |
| 无网络、密钥不进入前端、CSRF/Host 校验 | 测试夹具阻止外网；原有安全测试扩展覆盖新接口；发布检查 |

工作负载测试包含 10 组端点，其中 6 组来自 97 路两个方向，均不以手写完整路线作为搜索答案。
冷查询、重复查询和独立 tracemalloc 分配测试分开运行；不把少量测量当作算法普遍提速证据。
性能与内存测量不含输入路网加载，也不是浏览器响应总时间或进程 RSS。

本轮执行结果：完整 Python 测试 **314 passed**；既有快捷案例与新站点流程的 Playwright
检查均通过，视口为 1440、390、320 像素，无页面 JavaScript 异常或横向溢出。
新流程有一个预期的 HTTP 400（故意选择未覆盖站），不属于运行失败。
桌面和手机截图人工检查无控件遮挡；图片保存在本机忽略目录 `output/playwright/`。
`python -m tools.release_check` 检查 Git 可发布工作文件，未发现命中的密钥/令牌模式；
这是工作树检查，不是 Git 历史安全审计。`git diff --check` 通过。

## 后续边界

本轮不提供地址定位、地图选点、验证步行网、全岛环线路由、真实票价或赶车概率。
若继续扩到全岛，需要事件级环线求解与大路网预算验证；不应直接把完整 CSV 接到当前枚举器。
公开导航服务和新增个人数据采集仍需单独审查。
