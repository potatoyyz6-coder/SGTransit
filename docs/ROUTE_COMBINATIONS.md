## 查看案例

从仓库根目录运行 `python -m experiments.local_app`。
选 Information Technology 快捷案例，或用自选站点指定本地网络、
`16189 → 42171`、半径 0、`2026-10-23 10:00` SGT 参考时刻。

默认“组合视图”读取这次查询的全部默认参考候选，不只读取首页的代表方案。
先选 151，沿继续乘坐的分支可到 Blk 109。
此参考网络的候选允许在这里继续坐 151，或换乘 52、61、154、184。
这些选项由保留的有向站序与已有候选生成；不是额外写入的路线答案。
154 到 Bef Dunearn Rd，不能把它误写成与其他车一样到 Pei Hwa。

选择 61 后，它与其他车在共同走廊上的状态仍不同：
在 61 上继续坐不新增等待、缓冲或换乘；从别的服务转到 61 则有新的上车成本。
共享后段列出各服务的到达状态数量，代表对应原始路线数，不是到站概率。
选项较少可能来自本次有界候选搜索，不能据此断言现实中没有其他车。

完整路线列表分页显示原始 ID、服务、换乘站变体与时间分项。
“采用此路线”仍调用原有详情和途中参考；不会采用一条尚未确定的组合。
“独立路线”标签保留原首页代表列表。接驳未知时不产生门到门总时间。

## 展示模型

`src/sg_transit/route_combinations.py` 是独立只读索引：

1. 验证每条原始路线，将乘车段展开为带完整服务方向 ID 的相邻站连接。
2. 按实际起终点建立前缀树，每个节点对应原始路线 ID 的连续区间。
3. 只允许选择当前前沿的直接子分支，后续只从兼容原始路线中产生。
4. 相同物理站序的并行服务共用站点标签；方向、服务和路径成员关系不丢失。
5. 共同物理后段只是展示注释，不是允许绕过前缀约束的新连接。
   到达共同站时的前一服务逐路线检查，分别统计继续乘坐和换乘。
6. 连续同车、无分叉的中间站折叠，原始完整站序可展开分页查看。

不使用 `SharedSuffixPolicy` 的边并集生成新路径，也不接入碎片索引实验。
图上的两个连接即使接在同一站，没有原始路线支持整段选择，也不能成为新分支。
完整 ID、模型时间和换乘数均来自原查询，不在显示层重新估时。

## 本机接口

`POST /api/route-combinations` 是只读查询，沿用 Host / Origin / CSRF / 3 小时过期校验。
虽然使用 POST，接口不采集数据、不更新路线，也不改变乘车状态。

```json
{
  "plan_id": "from-api-plan",
  "origin": "16189",
  "destination": "42171",
  "selection": [],
  "choice_page": 0,
  "route_page": 0
}
```

`selection` 中的分支 ID 必须来自该 plan / OD 的上一层响应，按顺序追加。
所有完整路线引用都可用原 `/api/detail` 查看。
`expand` 为响应中路段 ID，`stop_page` 为站序页；更换分支后须重置展开状态。
`graph_page` 为图节点页。每页至多 60 个展示节点（含展开站点），
每处分支和完整路线每页各 8 项，站序每页 24 站。
隐藏数量明确返回，分页不会截掉索引中的候选。
图分页固定预留 24 个展开站点名额，因此折叠时每页最多 36 个路段节点；
展开时不移动页边界，总展示节点仍不超过 60。

共同后段的服务标记可以查看支持它的原始路线。
对应 `inspect: {"segment": 路段ID, "service": "61-D2"}` 只筛选详情引用，
不改变已选前缀或创造新分支；`reference_count` 是该筛选的数量，
`compatible_count` 仍是前缀兼容候选数。

索引随 plan 缓存在本机内存，沿用最多 3 个 plan 的生命周期。
同一 plan 内的时刻固定；其他查询时刻、实际端点不会混成同一方案。
被模型排除的候选只报告数量和原因；缺少运营信息的默认模型参考继续标未知。
